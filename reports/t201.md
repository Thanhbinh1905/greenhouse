The t201 change did not alter a first-pass prompt, input or budget. `reviewExecution` calls `reviewExecutionPaths` with `selected == nil` on the first pass; path filtering runs only when `selected != nil`. For each of the five cases, `Intent`, `Target`, `Head`, `Diff`, `Paths`, `ReviewBudget`, and `ToolCallBudget` match t200. The t201 values remain 3 minutes and tool-call budgets 24, 9, 19, 6, and 32. `main` and t201 reruns used the same candidate heads and these same path and budget values.

The t200 prompt does differ from the current prompt in two finding-schema fields: current `reviewContract` includes `conflicts` and `target_introduced`. That prompt change came from main commit `abdfeea` before t201, not this branch. The Criteria arrays for these cases are empty; their config and snapshot identifiers differ between runs. This is a baseline-version confounder, not a first-pass change introduced by t201.

No baseline detection was dropped by a follow-up merge, and no follow-up replaced a first-pass finding; none of these five cases ran a follow-up. The findings judged `different-defect` were not equivalent to the expected claims. Reruns reproduced expected detections for `posse-t1222-c6403c40` and `posse-t1222-c8af1296` on at least one run, and for `posse-task-1241-r2` on multiple runs. The expected claims for `posse-t1222-41abce87` and `posse-t1222-e86dccac` were not reproduced in four additional attempts each. This supports reviewer run-to-run variance for some losses; the other two may be persistent misses or rare baseline detections. The evidence does not identify a defect in t201 follow-up logic. The prompt version difference from t200 also limits strict before-and-after attribution.

## Risk and rollback

A follow-up uses another unit of the existing review budget and can increase review cost and latency. Revert this change to restore single-pass settlement. No data migration is needed; follow-up state is stored in run JSON and omitted when empty.
